# 5. IMPORTANT WORKFLOW INTERPRETATION

The default engagement sequence is:

```text
Eligible Post #1
      ↓
LIKE

Eligible Post #2
      ↓
LIKE

Eligible Post #3
      ↓
AI evaluates content

If relevant:
      ↓
LIKE
      ↓
Generate meaningful comment
      ↓
Approve/Post
```

The system must use **eligible posts**, not simply count arbitrary elements on a LinkedIn page.

Do not treat the following as posts unless explicitly configured:

* Comments
* Advertisements
* Suggested content
* Job advertisements
* Notifications
* UI elements
* Unrelated content

# 6. ARCHITECTURE PRINCIPLE

The system must have clear separation between:

```text
React UI
      ↓
FastAPI
      ↓
Agent Controller
      ↓
Workflow Engine
      ↓
AI / Scheduler / Platform Adapter
```

Claude should NOT directly control arbitrary external actions.

Claude is the reasoning layer.

The workflow engine controls deterministic execution.

Example:

```text
Claude:
Post relevance = 87

Workflow Engine:
87 >= configured threshold of 75

Action Executor:
LIKE_POST
```

This separation is mandatory.

# 74. FINAL RULE FOR CLAUDE CODE

Whenever implementing an AI agent:

8. Validate Claude's response.

This requirement applies to ALL current and future agents.

# 81. PROVIDER FACTORY

```json
  "reason": "The post directly discusses...",
  "riskFlags": []
}
```

Both providers must return data that can be validated using Pydantic.

Do NOT assume that a local model will always produce valid JSON.

Implement:

```text
LLM Response
      ↓
Parse
      ↓
Validate with Pydantic
      ↓
Valid?
   /     \
 YES      NO
  |        |
Continue   Retry / Repair
           |
       Still invalid?
           |
          Fail
```

Never execute external actions based on unvalidated LLM output.

---

# 84. STRUCTURED OUTPUT FALLBACK

Because local models may have different structured-output capabilities, implement a provider-neutral mechanism.

Preferred order:

```text
1. Native structured output if supported
2. JSON schema / constrained output if supported
3. Strict JSON prompt
4. Parse response
5. Validate with Pydantic
6. Retry once or twice if invalid
7. Fail safely
```

The workflow engine must never assume that the model is reliable simply because Claude previously returned valid output.

# 86. PROMPT MANAGER

Create:

```python
PromptManager
```

Responsibilities:

```text
Load prompt
Select version
Inject variables
Compose common rules
Return final prompt
```

Example:

```python
system_prompt = prompt_manager.load_system_prompt(
    agent_name="post_evaluator",
    version="v1"
)

user_prompt = prompt_manager.load_user_prompt(
    agent_name="post_evaluator",
    version="v1",
    variables={
        "post_content": post.content,
        "candidate": candidate,
        "campaign": campaign
    }
)
```

The provider then receives the generated prompts.

# 91. LOCAL MODEL MUST BE A DROP-IN REPLACEMENT

# 92. PROVIDER CAPABILITIES

Because local models may not have exactly the same capabilities as Claude, create a capability model.

Example:

```python
class LLMCapabilities:

    supports_structured_output: bool
    supports_tool_calling: bool
    supports_streaming: bool
    supports_vision: bool
    max_context_tokens: int
```

Each provider reports its capabilities.

Example:

```text
ClaudeProvider
    structured_output = YES
    tool_calling = YES
    streaming = YES

LocalLLMProvider
    structured_output = MODEL DEPENDENT
    tool_calling = MODEL DEPENDENT
    streaming = YES/NO
```

Do not assume every local model supports every feature.

# 93. SAFE CAPABILITY HANDLING

If an agent requires a capability that the selected provider/model does not support:

Do NOT silently fail.

Return a clear application error:

```text
LLM_CAPABILITY_UNSUPPORTED
```

Example:

```text
The configured local model does not support the required
structured-output capability for this agent.
```

Allow the configuration to be changed.

# 100. FINAL REQUIREMENT

The AI architecture must be designed around this principle:

> The application owns the agent logic. The provider owns model execution.

Therefore:

```text
Agent Logic
    ≠
Claude

Agent Logic
    ≠
Ollama

Agent Logic
    =
Provider-independent business logic
```

The final implementation must allow:

```text
CLAUDE
   ↓
LOCAL GPU
   ↓
ANOTHER OPEN MODEL
   ↓
FUTURE LLM PROVIDER
```

without rewriting the application.

The initial implementation must use:

```env
LLM_PROVIDER=claude
```

for laptop development.

The architecture must already support:

```env
LLM_PROVIDER=local
```

for future GPU deployment.

Do not postpone this abstraction until the GPU is available. Implement it from the beginning.
